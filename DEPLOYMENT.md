# Deploying ShabytBio for the classmate beta test

Everything code-side is done and committed to a local git repo. What's left needs your own accounts (GitHub, MongoDB Atlas, Render) — I can't create these for you. Follow these in order; each one only takes a few minutes.

## 1. MongoDB Atlas (free, forever) — stores accounts, history, review data

1. Go to https://www.mongodb.com/cloud/atlas/register and sign up (no credit card needed for the free tier).
2. Create a **free M0 cluster** (it'll suggest this by default — just pick a cloud provider/region close to you, e.g. AWS + a nearby region).
3. When prompted, create a **database user** (a username + password — save these, you'll need them in the connection string). This is separate from your Atlas login.
4. Under **Network Access**, add `0.0.0.0/0` (allow access from anywhere). Render's free tier uses dynamic IPs, so you can't whitelist a specific one.
5. Once the cluster is ready, click **Connect → Drivers**, choose Node.js, and copy the connection string. It looks like:
   `mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
   Replace `<username>`/`<password>` with the database user you made in step 3.

6. Add it to your local `.env` file (the one in your project root — never commit this file):
   ```
   MONGODB_URI=mongodb+srv://youruser:yourpassword@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

7. **Preserve your existing test data** (your account, the uploads you already tested): in your terminal —
   ```
   cd ~/ShabytBio
   node scripts/migrate-json-to-mongo.js
   ```
   This copies your local `data/*.json` into Mongo. Safe to run more than once.

8. Restart your local server (`npm run dev`) and confirm everything still works locally, now running on Mongo instead of local files.

## 2. GitHub — hosts your code so Render can deploy it

1. If you don't have one, sign up at https://github.com.
2. Create a **new repository** (github.com → the `+` icon → New repository). Name it `shabytbio`. Leave it empty — don't initialize with a README (you already have code).
3. In your terminal, in the project folder, connect and push:
   ```
   cd ~/ShabytBio
   git remote add origin https://github.com/YOUR-USERNAME/shabytbio.git
   git branch -M main
   git push -u origin main
   ```
   (GitHub will prompt you to sign in — follow its instructions, likely a browser popup or a personal access token.)

Your code (not your `.env`, not your `data/` folder — both are gitignored) is now on GitHub.

## 3. Render — actually hosts the running app

1. Sign up at https://render.com and connect your GitHub account when prompted.
2. Dashboard → **New → Blueprint**. Point it at your `shabytbio` GitHub repo. Render will read the `render.yaml` file already in your repo and pre-fill almost everything.
3. When it asks for the secret environment variables, paste in:
   - `GEMINI_API_KEY` — from your `.env`
   - `GOOGLE_CLIENT_ID` — from your `.env`
   - `MONGODB_URI` — the same connection string from step 1
   (`SESSION_SECRET` is auto-generated by Render — you don't need to touch it.)
4. Click **Apply** / **Create**. First deploy takes a few minutes. When it's done you'll get a URL like `https://shabytbio.onrender.com`.

**Free tier heads-up:** the app "sleeps" after 15 minutes with no traffic, and the next visit takes about a minute to wake back up. Worth a one-line warning to your classmates ("first load might be slow, that's normal — wait ~1 min").

## 4. Google Cloud Console — let sign-in work on the new domain

Google Identity Services only allows sign-in from domains you've explicitly registered. Without this step, "Sign in with Google" will fail on the live site even though it works on localhost.

1. Go to https://console.cloud.google.com/apis/credentials and open your existing OAuth 2.0 Client ID (the one whose value is your `GOOGLE_CLIENT_ID`).
2. Under **Authorized JavaScript origins**, click **Add URI** and add your Render URL exactly, e.g. `https://shabytbio.onrender.com` (no trailing slash).
3. Save. Changes can take a few minutes to propagate.

## 5. Final smoke test (do this yourself before sending the link out)

Open the Render URL in an incognito/private window (so you're not using a cached local session) and check:

- Sign in with Google works
- Upload a file, get results back
- Diagrams tab, Review button, all tabs render correctly
- Sign out, sign back in — your account/history is still there (proves Mongo persistence is actually working, not just the app running)

## 6. Sending it to classmates

Once the smoke test passes, share the Render URL. Given your timeline — beta this week, fixes after, real launch next week — it's worth asking testers for quick feedback (even just "what broke" in a group chat) rather than a formal survey, so you can move fast on fixes before the real launch.

### Rate limit + caching (added after checking your real Gemini quota)

Your confirmed free-tier limit is **5 requests/minute** for Gemini 2.5 Flash. Two things now protect against that:

- **Caching**: if two students upload the exact same file with the same (or both blank) focus instructions and grade, the second one gets an instant cached result — zero extra Gemini calls. Personalized focus instructions always get their own fresh result, never someone else's cached one.
- **Queueing**: if more than 5 requests land in the same minute, extras wait in line automatically instead of erroring out.

No setup needed — both are on by default. If you ever get a rate limit increase from Google (or switch models), update the limit via an optional env var: `GEMINI_RPM_LIMIT=<new number>` in `.env` and in Render's environment settings.

### Related Videos tab (real YouTube videos, added after beta feedback)

Each upload now also gets 2-3 real, relevant YouTube videos on the same topic, embedded directly in a new "Videos" tab — not AI-generated, just a search against YouTube's own catalog for whatever the material is actually about.

To turn this on:

1. Go to https://console.cloud.google.com/apis/library — same Google Cloud project you already use for sign-in.
2. Search for **"YouTube Data API v3"** and click **Enable**.
3. Go to **APIs & Services → Credentials → Create Credentials → API key**. Copy the key it gives you.
4. Add it as `YOUTUBE_API_KEY=<your key>` to your local `.env`, and as a new environment variable in Render (Environment tab → Add Environment Variable).

Until this is set, the Videos tab just quietly won't appear — it fails gracefully and doesn't affect anything else, so there's no rush and no risk in leaving it for later.

Free quota is generous (10,000 units/day, each search costs 100 units = 100 searches/day) and results are cached for 24 hours per topic, so repeated searches for the same lesson don't burn extra quota.
